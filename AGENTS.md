## Required completion workflow

The founder explicitly instructed on 2026-09-05: always commit and push code after completing your work.

- After completing scoped work and passing the relevant checks, commit the code and accompanying documentation on `main`, then push to `origin/main`.
- This standing authorisation applies to ordinary tasks and automation runs, including the existing Git-triggered deployment. Do not ask for separate routine commit or push confirmation.
- Preserve unrelated edits. Verify that the remote contains the final commit and report any remaining uncommitted work accurately.
- If publication is blocked by authentication, branch protection, unavailable network access or mandatory approval enforcement, report the exact blocker. Do not bypass an explicit tool rejection or claim unpublished work is complete.
- This does not authorise destructive history rewrites, secret changes or unrelated deployments.
